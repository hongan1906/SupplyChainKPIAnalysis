# Supply Chain KPI & Inventory Analysis (SQL)

Linking sales demand, bill of materials and purchase-order receipts to answer three planning questions:

1. **Which products drive revenue?** — revenue share and ranking
2. **Where should planning effort go?** — Pareto curve and ABC classification
3. **Which components are tying up stock or at risk of running out?** — BOM-exploded consumption vs. receipts

Built in SQLite with CTEs, joins and window functions; Python loads the data and draws the charts.

> **Data:** fictional dataset for one year (2025) generated by `generate_data.py`: 40 products, 60 components, 1,200 sales order lines, 230 PO lines. See `supply_chain_data.xlsx`.

## Data model

| Table | Role | Columns used in the SQL |
|---|---|---|
| `sales_orders` | Demand | `product_id`, `quantity`, `unit_price` |
| `bom` | Components per finished product | `product_id`, `component_id`, `quantity` |
| `po_lines` | Supply (receipts) | `component_id`, `delivered_qty` |
| `components` | Master data | `component_id`, `component_name`, `category`, `unit_cost` |

```
sales_orders ──product_id──▶ bom ──component_id──▶ components ◀──component_id── po_lines
   (demand)                (explosion)              (master)                    (supply)
```

The Excel file also contains `products`, `customers`, `vendors` and `purchase_orders`, plus order, ship and receipt dates for later service-level analysis.

## 2. Pareto & ABC classification

Products are sorted by revenue and a running total is computed. Each product is classed by where it *starts* on the cumulative curve: **A** = first 80% of revenue, **B** = next 15%, **C** = last 5%.

![Pareto curve with ABC classes](screenshots/pareto_analysis.png)

| Class | Products | % of products | % of revenue | Planning treatment |
|---|---:|---:|---:|---|
| **A** | 9 | 22.5% | 80.1% | tight forecasting, highest service-level target, weekly review |
| **B** | 16 | 40.0% | 15.1% | standard review cycle |
| **C** | 15 | 37.5% | 4.8% | simple reorder rules, candidates for range rationalisation |

**Finding:** the business follows the 80/20 rule almost exactly. 15 C-class products bring in under 5% of revenue but still need components, stock and planning time.

## 3. Component consumption vs. receipts

Sales are exploded through the BOM to get component demand, then compared with what was received on purchase orders.

- **Consumption ratio** = consumed ÷ received
- **Net stock** = received − consumed, valued at `unit_cost`

![Component movement status](screenshots/inventory_turnover.png)

| Status | Rule | Components | Net stock value | Share |
|---|---|---:|---:|---:|
| Slow-moving (excess risk) | ratio < 0.2 | 17 | €869,789 | 56% |
| Normal | 0.2 – 0.6 | 25 | €484,042 | 31% |
| Fast-moving (stockout risk) | ratio ≥ 0.6 | 15 | €193,213 | 12% |
| Shortage / missing opening stock | net stock < 0 | 2 | – | – |
| Demand without receipts | received = 0, demand > 0 | 1 | – | – |

Largest excess positions:

| Component | Category | Received | Consumed | Ratio | Excess value |
|---|---|---:|---:|---:|---:|
| C035 | Cables | 53,824 | 6,875 | 0.13 | €258,220 |
| C039 | Packaging | 38,977 | 4,986 | 0.13 | €189,670 |
| C048 | Plastics | 18,606 | 2,628 | 0.14 | €121,433 |
| C055 | Electronics | 33,866 | 5,644 | 0.17 | €115,428 |

**Findings**

- **Over-buying is concentrated.** Four components hold €685k, almost half of all leftover stock value. Cables (€288k) and Packaging (€191k) are the categories to review with procurement first.
- **Shortages exist alongside excess.** C033 (Packaging) and C037 (Electronics) had more demand than receipts, and C059 (Cables) was consumed but never purchased. These are either missing opening stock or a sourcing gap, and should be checked before trusting the numbers.
- **Fast-moving parts need a buffer.** 15 components used over 60% of receipts. If they feed A-class products, they are the first candidates for safety stock.

## Assumptions & limitations

- **No opening stock.** Net stock is a period balance (receipts − consumption), not an on-hand figure, so true inventory age and days of supply can't be measured.
- **Sales = production.** Component consumption assumes every unit sold was built from the BOM in the same period (no finished-goods buffer, no scrap).
- **Consumption ratio is a proxy.** Standard inventory turnover (cost of goods used ÷ average inventory) needs inventory snapshots over time.
- Status thresholds (0.2 / 0.6) and ABC cut-offs (80 / 95) are conventional starting points, not tuned to this business.
- The data is synthetic, so the findings illustrate the method rather than describe a real company.

## How to run

```bash
pip install pandas openpyxl matplotlib numpy
python generate_data.py    # optional: rebuild supply_chain_data.xlsx (change SEED for new data)
python run_analysis.py     # Excel → SQLite → SQL queries → results/*.csv + screenshots/*.png
```

You can also edit `supply_chain_data.xlsx` directly and re-run `run_analysis.py`. The charts and CSVs update automatically; the numbers written in this README do not, so refresh them from `results/`.

To run the SQL on its own:

```bash
sqlite3 supply_chain.db < Assignment_Script.sql
```

```
├── supply_chain_data.xlsx    raw data (one sheet per table)
├── Assignment_Script.sql     the analysis
├── generate_data.py          synthetic data generator
├── run_analysis.py           pipeline: load, query, chart
├── results/                  query outputs as CSV
└── screenshots/              charts used in this README
```
